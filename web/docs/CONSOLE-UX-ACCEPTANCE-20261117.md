## 重跑步骤

1. 使用隔离 MySQL `campushub_test`、回环业务 `8082`、独立运维 `8092` 和独立媒体、控制、产物、备份目录。确认其实际配置后再执行部署、重启和恢复。使用当前后端工作区 `69b2f3a` 的同一 JAR 分别启动打包及解包模式。
2. 默认端口为业务 8080、运维 8091。此验收固定使用受控端口，开发入口仍分别为 5174、5175。候选账号、数据库和运行配置留在本机。
3. 从 `web` 分别启动两个开发入口。另在仓库根目录设置本机隔离目录并运行脚本。假定隔离测试作者、普通测试读者、用于撤销的测试读者和两套管理身份已经建立；投币用例需要测试读者有奖励余额。需要重跑全部写用例时使用新隔离数据。

```powershell
# web 目录，分别在两个终端运行
$env:CAMPUSHUB_API_TARGET = 'http://127.0.0.1:8082'
npm run dev:admin
$env:CAMPUSHUB_OPS_TARGET = 'http://127.0.0.1:8092'
npm run dev:ops

# 前端仓库根目录。整组运维操作从业务端口停止开始
$env:CAMPUSHUB_CONSOLE_FIXTURE = (Resolve-Path tmp/console-ux-20261117/fixture).Path
node web/tests/ops-acceptance-browser.mjs --packaged
# 切换为同 JAR 解包的独立运维启动方式后
node web/tests/ops-acceptance-browser.mjs
node web/tests/console-ux-browser.mjs
node web/tests/management-browser.mjs
```

4. 管理端实测在案件列表选择举报／待受理，从固定版本进入巡查再返回。认领后在另一会话提交后续治理决定来制造真实冲突。保留原决定和答复，重新核对修订，对投币标记失效并复查审计，再确认闭案。归并临时同义分类并查询源指向。撤销隔离账号后用本人真实接口读取撤销理由、通知及申诉详情。
5. 运维端从业务不可达时登录。运行查询时拦截一次真实日志请求。在部署首次取得原任务后拦截下一次 GET，确认仍显示原任务并恢复。完成重启与带媒体的完整备份。恢复前查看目标备份、快照、覆盖范围和预检，确认后核对实际 URL、数据库及图片。
