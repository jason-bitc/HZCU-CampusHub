## 复现和核对步骤

### 修改前记录

基线运行在同一个 5173 开发入口，数据来自 8080。打开 A01 长文并在 390×844 点击“目录”，列表没有当前章节标记。用验收读者打开“站内通知”，确认已有通知后拦截通知列表的 GET 并重载，看到错误状态和空出的列表区。用验收作者打开 A03 的编辑器，在 390×844 查看正文、预览与发布操作。桌面资料页核对资料和联系设置共用同一个结果出口。上表其余基线行为由 `67a55bb` 页面代码核对。

### 修改后验收

| 场景 | 浏览器操作与期望 |
| --- | --- |
| 岗位、长文、返回 | 在 390px 组合筛选选 A01 对应岗位，记住卡片位置。键盘进入文章，打开目录并跳到投递检查清单。双击收藏时只发送一次，即使响应在浏览器侧丢失也能从真实接口回读。返回恢复卡片焦点与位置。拦截下一次筛选读取，旧内容带说明，解除拦截后重试。 |
| 游客登录、图片 | 游客在 A01 跳章后从目录登录，回到原章节。只中断 A03 一次图片请求，图片原位出现重试，点击后读取原来资源。 |
| 评论 | 在 A01 新建临时评论，显示真实提交结果。键盘打开本人删除对话框后用 Escape 取消，再确认删除并核对服务端结果。 |
| 通知 | 读取列表后拦截下一次刷新，逐条比对旧通知和未读数。解除拦截再刷新。有未读样本时先拦截标记请求，核对状态不变，再通过真实标记和读取校验总数。 |
| 上传、缺项、离开保护 | 建新草稿，点击“预览并发布”，逐项点击检查清单并核对实际焦点。以 A03 的真实图片上传，拦住响应时继续写正文，模拟已落库的回执丢失，用相同请求标识和原图重试。核对最新输入及唯一图片引用。切换正文与预览，检查选区。用 Escape 取消一次离开提示，核对输入仍在。 |
| 真实 409、公开发布 | 保留本地新增段落，另发真实保存请求推进同一草稿修订。在浏览器保存收到 `409 REVISION_CONFLICT`。对照本机与服务器字段，检查本机正文、图片和新增段落。取消使用服务器版本后选择手动合并，再补齐条件、预览、确认发布，回读公开全文。 |
| 下架与恢复 | 在工作区选临时文章，用 Escape 取消一次并核查焦点。确认下架后卡片变为作者已下架，公开接口返回 404。恢复后同卡片变为已发布，公开接口返回 200。 |
| 资料与联系 | 分别修改并保存昵称、关闭联系入口后的联系信息，核对各自反馈。各自重新读取后与接口值一致，最后恢复验收账号原字段。 |
| 案件与申诉 | 在 390px 打开真实案件的时间线。注入一次读取失败，确认历史和答复保留后重试。核对本人行为申诉页面，另用认证已撤销的账号打开撤销原因和复核答复。 |

### 重跑方式

1. 在 `127.0.0.1:8080` 启动版本 `69b2f3a` 的业务服务，连接已有隔离 MySQL `campushub_test`。测试数据包含作者、读者、认证已撤销账号和本人的复核记录，以及通过创作接口导入的 A01、A03 完整文章。需要核对标为已读的场景时，保留至少一条未读通知。
2. 在 `web` 安装锁定依赖后运行下列命令。从前端仓库根目录运行浏览器脚本。环境变量指向本机验收目录，不将账号、令牌或数据库配置放入 Git。

```powershell
# 在 web 目录
$env:CAMPUSHUB_API_TARGET = 'http://127.0.0.1:8080'
npm run dev
# 在另外一个终端的 web 目录
npm test
npm run build
# 在前端仓库根目录
$env:CAMPUSHUB_WEB_UX_FIXTURE = (Resolve-Path tmp/acceptance-fixture-live).Path
$env:CAMPUSHUB_WEB_SCREENSHOT_DIR = (Resolve-Path tmp/web-ux-20261117).Path
node web/tests/web-ux-browser.mjs
```

脚本读取本机隔离环境的 `closure.private.json`、`business.private.json` 和 `demo-import.json`。本机证据文件 `tmp/web-ux-20261117/web-ux-results.json` 按来源记录 HTTP 方法、路径、状态、业务码和追踪号，不保存响应正文、密码或令牌。浏览器中断与转发场景在记录中标明来源，验收文章和临时评论按业务接口清理。

## 结果及截图

- 自动化，`npm test` 通过 24 项，新增前端和服务端发布缺项映射回归 1 项。读者作者、社区管理和独立运维三个入口构建成功。
- 浏览器 10 项通过，页面未捕获异常 0。桌面 Chrome 使用 1440×1000 与 390×844，包含 Enter、Escape、目录与输入焦点检查。通知、图片、收藏、上传和案件的断线用例由浏览器定向中断指定请求。真实冲突、公开 404、恢复 200 和认证受限 403 均来自业务后端。
- 最终记录 123 条真实业务响应，120 条成功。其余三条为预期的 403 认证受限、404 下架不可读、409 修订冲突。标记已读成功及断网保持未读的分支在同环境较早一轮使用尚未读的通知验证，最终回归时该账号已无未读。
- 通知已读接口成功只返回 `readAt`，未读总数以随后的列表读取为准。工作区状态回执返回 `state` 和 `revision`，更新时间与分页由后续列表读取更新。接口契约无需调整。
