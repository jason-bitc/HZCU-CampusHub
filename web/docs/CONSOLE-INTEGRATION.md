## 真实接入与原型示例

默认路径为实际接入状态。缺失后端时显示准确原因，状态为未读取/未核验，执行按钮禁用；不会使用演示数字填补空缺。校园会话不授管理或运维权限。

每页顶部“查看原型示例”切换 `?preview=1`，便于逐屏对照原型。该模式有持续可见的只读标记，数据明确为原型人物、编号和状态；没有管理/运维 API 调用，不能执行真实操作。导航只切换示例页面。示例模式不是后端成功联调证据。

1440×960 桌面基准使用原始 SVG 的208px侧栏、66px顶栏、配色、主要卡片和表格比例。390px 窄屏折叠侧栏并把表格滚动限制在容器内。来源“原型演示 / 已授权管理员”等文字在实装中明确区分为示例身份或真实核验身份，避免假授权。

## 已有社区合同适配

- 登录 `POST /api/v1/admin/auth/login` 只发送 `login/password`；退出 `POST /api/v1/admin/auth/logout` 无请求体。身份来自 `GET /api/v1/admin/me`。
- 管理 Token 使用独立存储、过期定时器和请求层，只发往 `/admin/`；直接进入管理路由时等待路由确定后初始化管理身份，不提前恢复校园身份。管理401只清理管理会话和管理副本。
- 案件列表只发送 page/size/snapshot/kind/state；没有向后端臆造负责人筛选参数或管理计数接口。
- claim 发送 expectedRevision/requestId；release 另含非空reason；decisions 完整发送 outcome/reply/internalNote。前端仅开放当前受理人与现有状态允许的动作；最终权限仍由服务端校验。
- 发布后治理未实现时，`REQUIRES_GOVERNANCE` 仅进入待后续治理，不伪称已经隐藏内容、限制账号或扣减贡献。
- 待确认写请求先按当前管理主体保存原键、原修订和原正文，刷新后按原请求核对。新修订冲突不会自动覆盖；结束本机待确认请求前先读取并让用户核对当前状态与历史。
- 案件上下文不回退到公开图片链接；本案证据与媒体经 `/admin/cases/{caseId}/media/{imageId}` 携带管理 Bearer 下载后用 Blob 展示，退出或离开页面释放资源，Token 不进入URL。

## 后端后续交接

请以正式合同补充治理的读写能力和独立运维的授权、状态、固定动作、任务、日志、版本/备份清单、预检查、失败保护、幂等与互斥规则；前端目前没有猜测这些路由和字段。

独立运维需要与业务服务分别授权、存储任务及提供接口。接入时应指定独立服务地址与代理，不能简单复用校园/社区 Token，也不能用业务库登录取代运维身份。当前 Vite 的 `/api` 代理仍只针对已有业务后端，尚未配置一个不存在的运维服务。

社区管理员完整成功联调需本机已有授权账号的私密配置。当前只有校园测试凭据，因此只执行真实普通身份拒绝、既有真实用户回归及明确标注的管理合同模拟。没有管理员真实操作、部署、重启或数据恢复验收。
