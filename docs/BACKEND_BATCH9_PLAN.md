## 2 管理身份与授权

普通用户注册仍只创建USER，不通过请求体、邮箱域、前端菜单或JWT自报角色授予权限。当前V3的platform_user.role约束仅允许USER，不能修改旧迁移或将既有全部认证路径放宽来容纳管理员。

本批采用独立社区管理账号、密码与会话存储，管理接口使用 `/api/v1/admin` 命名空间。管理账号仅有本批案件处理能力，不等于普通校园账号，也没有运维权限。普通Bearer不能访问管理接口，管理Bearer不能调用普通创作、奖励、账本或其他用户接口；两类账号即使内部数字ID相同也不能混淆。

管理密码复用当前PasswordEncoder，数据库只存会话令牌摘要。每次管理请求校验会话及管理账号状态，不靠已签发的静态角色缓存；退出、过期或账号停用立即阻止后续管理请求。登录错误不暴露账号存在与否，必要登录失败限流及其固定参数在最终合同说明。所有管理接口、敏感图片和失败响应使用no-store，先鉴权再校验目标或读取文件。

提供本机管理员初始化/凭据重设工具和操作说明，密码通过隐藏输入或受忽略配置读取，不放命令行、迁移、源码、日志或文档；不创建默认管理员或固定口令，不自动把王晨/刘景浩普通账号提升为管理账号，不通过公开API注册管理员。测试使用本次随机管理身份；真实演示管理账号由用户按说明本机初始化。

审计增加明确的主体类型或等效不混淆的命名空间，区分USER与COMMUNITY_ADMIN。既有审计默认仍代表USER，不将历史记录重写成管理操作；新增管理操作必须能定位实际管理主体及案件。独立运维身份不在本批创建，也不因社区管理权限自动获得。

## 3 反馈和举报提交

统一案件模型区分FEEDBACK与REPORT。举报须关联当前用户能查看的文章或评论，类别至少包括ADVERTISEMENT、MISLEADING_CONTENT、OTHER；一般反馈可关联当前可见文章/评论，也可无目标，类别可为BUG、SUGGESTION、OTHER。类别是提交者的主张，不是系统违规判决。

提交字段保持精简：类型、类别、可选目标类型与目标ID、说明正文、可选imageIds和requestId。不强制额外标题、真实姓名或联系方式。正文有必要的非空与可配置技术边界，不设最低字数；图片无固定业务张数上限，沿用已确认的单文件/像素/请求等技术边界。未知字段、重复字段、错配类别/目标、额外userId/role/status/assignee字段拒绝。

服务端从目标确定articleId、commentId和提交时公开articleVersionId，客户端不得指定任意版本或将评论挂到另一文章。目标必须在首次成功提交时可见；未知、下架、隐藏、删除或无有效公开版本统一404，不允许通过新举报探测隐藏内容。举报本人可见内容不额外禁止。

同一用户requestId、相同规范化内容和图片顺序重复/并发只产生一个案件；同键改内容409。成功键在原文后来不可用、服务重启后仍可重放本人最小回执；初次失败不记成功。不同键针对同一目标不直接吞掉，也不因举报次数自动隐藏文章、限制作者或扣贡献。

提交成功保存案件、必要关联、附件绑定、幂等回执和成功审计；任何必需写入失败全回滚。服务端生成提交者、时间和初始状态。不能把仅图片上传成功当案件已受理。

## 4 私人证据图片

提供独立案件图片上传/读取及元数据关系，复用现有安全图片校验和存储能力。上传必须属于本人，绑定时验证归属、状态和请求幂等；不得借用他人、文章/评论模块图片ID或任意文件路径当自己的证据。图片内容不进入运行日志。

未绑定图片仅上传者可读；绑定后仅提交者和具备案件权限的社区管理员可读。游客、其他普通用户、运维身份均不能访问，即使知道UUID或曾获得链接也不能绕过当前权限。管理读取使用案件限定入口，验证图片确实属于该案件或其已保存目标上下文，不开放任意媒体库浏览。

JPEG/PNG真实性、大小/像素、损坏、伪装、MIME、路径及软链接边界沿用当前实现，不降低原作者/评论图片规则。真实存储或校验失败返回明确失败，文件和数据库/审计故障有回滚或本次孤立文件清理，不影响旧用户文件。案件附件不得进入公开文章图片接口。

## 5 本人列表、状态和隐私

认证用户可稳定分页查询自己的案件及详情，包含本人提交内容、自己的附件、目标最小标识、当前状态、公开处理答复及允许查看的状态时间线。不能指定其他userId，猜测他人案件ID和图片ID不得读取。

原文后来不可用时，本人案件不重新提供隐藏标题、正文、原评论图片或管理员内部上下文。本人原提交说明与本人证据仍属于私人案件内容，可以继续查看，不因此向其他账号公开。内部工作备注、管理员登录名、私人凭据和他人身份材料不进入普通用户响应。

当前普通入口仍要求有效校园认证。受限/认证失效者必要申诉入口将在后续FR-M04专项实现，本批不能宣称该完整流程已具备。

## 6 管理受理与基础状态流转

管理待办支持类型/状态等必要筛选和稳定分页，详情提供提交说明、证据、受理人、修订、处理时间线及关联对象。管理人员可认领未分配案件；相同认领重试不重复变更，其他管理员不能静默抢占。释放本人认领须说明理由，重新成为待受理，不能把任意请求userId当管理主体。

| 状态/动作 | 本批语义 |
| --- | --- |
| OPEN | 已接收，待管理员受理 |
| PROCESSING | 已由当前管理员认领并处理中 |
| NEEDS_ACTION | 有待后续内容/账号治理进一步处置；保留负责人、说明和下一步，不冒称违规内容已隐藏 |
| CLOSED | 已答复反馈，或举报无需处理/重复案件已说明；结论须与实际动作一致 |

认领、释放及处理使用expectedRevision及小写UUID requestId；同一成功请求重复返回原回执，同键改内容冲突，新键使用旧修订409，避免覆盖另一管理人员决定。正式状态机、允许状态迁移、结论枚举和错误码在API固定，不允许客户端任意设置状态或负责人。

处理必须有给提交者可见的说明；内部备注单独存储并明确受限。反馈可按ANSWERED/RECORDED结束，举报可按NO_VIOLATION或DUPLICATE结束；确认需要隐藏/限制等实际动作的举报只能进入NEEDS_ACTION，不能仅修改案件为CLOSED便写成“已删除、已封禁、已退币”。本批无执行这些动作的接口。状态记录、管理主体、理由、修订、幂等回执及成功审计同事务保存，无删除案件/审计入口。

## 7 受控目标上下文

管理员可由案件一键查询关联文章的提交时公开版本、当前状态，以及关联评论和必要根/被回复上下文。文章版本必须由成功提交时的服务端关联确定，且确实曾公开；不提供任意版本ID检索，不读取从未公开的作者草稿。

原文下架、管理员隐藏或作者软删除后，管理端仍可使用必要的受控记录处理原案件，但该能力只在管理命名空间提供。当前前八阶段的普通文章、评论、收藏和媒体权限保持，不能为管理员方便放宽旧公共接口。

管理上下文需要的文章/评论图片通过案件限定管理入口校验原关联后返回；不能靠普通公开图片入口强行访问，也不能通过替换图片UUID遍历其他草稿或私人材料。上下文不足或文件确已缺失时明确标示可用性/失败，不编造快照、不自动抓取网盘和外站内容。只提供必要目标和上下文，不整库导出用户邮箱、联系方式、认证材料或币账本。

## 8 接口与交付合同

统一保留原code/data/traceId、HTTP状态、no-store和X-Trace-Id。默认分页1/20、size上限100，拒绝未知/重复参数及越权身份字段。确切字段、稳定分页方案、状态机、幂等回放及技术边界在正式API同步。

| 入口 | 计划能力 |
| --- | --- |
| POST /me/case-images；GET /media/case-images/{id} | 本人上传与受控读取证据 |
| POST /me/cases；GET /me/cases；GET /me/cases/{id} | 本人提交、列表及状态详情 |
| POST /admin/auth/login；POST /admin/auth/logout；GET /admin/me | 独立管理会话和当前案件能力 |
| GET /admin/cases；GET /admin/cases/{id} | 管理筛选列表、案件详情和处理时间线 |
| GET /admin/cases/{id}/context；GET /admin/cases/{id}/media/{imageId} | 必要目标上下文和案件限定媒体 |
| POST /admin/cases/{id}/claim；POST /admin/cases/{id}/release；POST /admin/cases/{id}/decisions | 认领、释放和基础处理 |

接口路径为实施起点，可依现有约定优化，业务和授权边界不得静默改变。管理登录之外的管理路径，包括非法ID/未知子路径，都须先验证管理会话；不能依赖前端隐藏菜单或只保护已知成功路由。私人图片需明确区分普通用户本人读取与管理案件读取，不能在旧普通AuthService.me上去掉USER限制。

## 9 迁移、日志和验证
