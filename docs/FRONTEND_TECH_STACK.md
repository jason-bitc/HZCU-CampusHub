# 前端技术选型与变更说明

变更标识 CR-G04-20261101-FE；2026年11月1日；依据为项目负责人本次明确选择及网页框架确认。该选择是需求与设计输入，不表示代码已经切换或联调通过。

## 当前技术方案

| 部分 | 技术与边界 |
|---|---|
| 微信小程序 | 原生WXML、WXSS、JavaScript及JSON配置，微信开发者工具运行和调试；不采用uni-app，不由网页构建结果转换小程序。 |
| 独立网页端 | Vue 3、TypeScript、Vite；分别满足读者、作者、社区管理和独立运维入口，按桌面长文和管理场景设计。 |
| 共用业务服务 | Java 21、Spring Boot、MySQL，既有JSON接口、校园邮箱密码账号及后端权限规则继续作为协作依据。 |
| 独立运维 | 运维网页访问独立运维接口和受控执行器，业务停机时仍可查任务；不能因网页使用同一框架而合并权限或依赖业务数据库登录。 |
| 工具与协作 | 微信开发者工具、VS Code、IntelliJ IDEA、MySQL、Postman、JMeter、Git/GitHub及SourceTree；WorkBuddy负责前端任务，Codex/GPT负责后端任务，学生负责审查和集成。 |

## 复用与分离

两个前端分别维护页面、组件、路由、平台适配、构建和回归。共享的是账号含义、API契约、错误分类、内容结构、规则、图标等可复用资源与测试场景；不承诺共享一套页面代码，也不再使用uni-app的条件编译或跨端打包流程。

小程序按原生能力处理请求、图片上传、存储和富文本呈现；网页通过独立API客户端处理同一业务。两端账号相同，会话凭据分别按接口规则取得和保存，不把浏览器Cookie自动带入微信。微信身份绑定仍为未来范围。Markdown复杂编辑在网页完成，小程序基础图文不得静默截断其他端内容。

## 分工与验证

王晨负责后端契约、校园认证和本人负责的移动业务对接；刘景浩负责独立网页阅读创作、社区及运维网页；双方完成原生小程序任务分解、场景与接口交叉复核。前端实际实现仍由对应开发对话推进。
