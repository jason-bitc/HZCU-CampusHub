## 2 业务与权限

### 2.1 认证后交流

沿用USER、ACTIVE、VALID及有效会话要求；游客和登录但未认证者不能读取评论、回复、评论者资料及评论图片，也不能新增。先检查访问者身份，再查询受限目标；无会话401、受限身份403、不可见目标404。

只有当前公开文章可读取评论及新增交流，原无真实作者的公开演示文章也可以作为明确DEMO的交流测试目标；不因演示文章没有作者就虚构文章作者。文章下架、管理员隐藏或删除后，旧评论及图片入口不泄漏内容，新增请求拒绝；恢复后仅原本可见且未删除/隐藏的评论恢复可见。

不要求评论者先发文章或建立作者主页。认证用户均可评论。评论者资料仅用允许公开的最小字段；当前账号受限或认证失效时不显示其受限个人资料或主页入口，历史评论正文的可见性按评论自身及文章状态处理，不能把认证状态解释成内容真实性。已认证、但没有公开文章的评论者可显示昵称，不提供一个无法访问的作者主页入口。

### 2.2 文字、图片与回复

评论正文使用普通文本，保留换行，网页后续按安全文本呈现，不解释成HTML或脚本。本批不做评论富文本编辑器。正文非空或至少有一张可用的本人评论图片即可提交；无最低字数，不允许只有空白且无图片。

建议技术默认值：正文最多10000个Unicode码点；JSON请求最多128KiB；图片沿用可配置的JPEG/PNG实际解码、10MiB单文件、12MiB multipart及2500万像素限制。不给评论设置固定业务图片张数上限，服务端仍须对整体请求、解析及SQL批量操作做有界处理。以上默认值在API中记录，不作为教师已批准参数。

按“主评论＋平铺回复”提供接口。主评论分页按创建时间和ID确定排序；回复页同样分页且保留replyToCommentId、根评论ID及必要的可见回复对象。允许回复同一根评论下的可见回复，通过关联表达关系，不递归返回无限深嵌套。跨文章引用、伪造根ID、未知或当前不可用回复目标拒绝。

创建评论使用独立客户端小写UUID请求标识。相同用户、相同标识与同一规范化业务内容的重试仅产生同一条评论；同标识不同内容返回409。图片上传另用上传请求标识，不与创建标识混用。并发相同创建/上传只能有一次业务效果；失败不能留下半评论、重复图片关联或虚假成功审计。

### 2.3 本人删除及上下文

本人可软删除自己的评论，包括自己发布在他人文章下的内容；文章作者只能回复，不能删除其他人的评论。未知或他人操作目标统一404。重复删除本人已删除评论返回同一终态，不新增成功变更记录，不误删他人回复。

删除或管理员隐藏的父评论保留不可用占位与结构标识，不返回原正文、图片或隐藏原因，也不级联删除其他人的正常回复。不可用父评论不能作为新的回复对象；已有正常后续回复仍可通过根线程读取并理解回复关系。管理员隐藏状态只能由后续治理权限处理，本人删除不能变相恢复。

文章不可公开时仍允许认证本人删除已知ID的本人评论，但不借删除响应返回隐藏正文或文章详情。此规则在接口文档明确，以便后续个人评论管理接入。

## 3 评论图片

评论图片使用独立元数据、归属及读取入口，不能直接借用文章作者上传接口。复用现有实际图片校验和受控文件存储基础，不复制另一套宽松校验。

- 上传时绑定上传者和目标文章，仅当前认证用户可在公开文章下上传。上传成功返回稳定图片ID及受限URL；未附着评论时仅上传者在文章仍公开的前提下可预览。
- 提交时只接受本人为同一文章上传且尚未用于另一条评论的有效图片。拒绝他人图片、本人其他文章的图、文章创作图和未知ID；同一评论重试不重复绑定。
- 附着到当前可见评论后，其他认证读者按文章及评论状态读取；评论删除/隐藏或文章不可见时，旧图片URL不得继续返回内容。终态删除评论的图片不再按“未附着预览”规则重新开放。
- 所有评论图片请求及失败均需要认证并no-store，不把令牌放URL；未知、未授权或不可见统一404，存储损坏/缺失按现有503语义反馈，不伪装成成功。
- 数据库与文件失败只处理本次新建文件，不能删除既有文章图或其他评论图。提交结果未知时不臆断回滚并删除仍可能被引用的文件；长期未使用文件清理和完整备份仍待后续设计。

## 4 接口契约草案

统一前缀 `/api/v1`，沿用成功 `code/data/traceId`、失败 `code/message/traceId`及X-Trace-Id。新增JSON、图片、成功和错误响应均no-store。最终字段及排序以同步后的API/Postman为准。

| 接口 | 行为 |
| --- | --- |
| GET /articles/{articleId}/comments?page=1&size=20 | 认证读取主评论分页，含必要占位、本人是否可删除及回复数量，不一次嵌入全部回复。 |
| GET /comments/{rootCommentId}/replies?page=1&size=20 | 认证读取一个根线程的平铺回复；父节点不可用时保留结构，不泄漏已删除/隐藏正文。 |
| POST /articles/{articleId}/comments | `{requestId,body,imageIds,replyToCommentId}`；replyToCommentId为空建立主评论，非空由服务端推导根节点，成功201返回创建回执。 |
| DELETE /comments/{commentId} | 认证本人软删除，成功200返回最小终态；他人404，重复终态幂等。 |
| POST /articles/{articleId}/comment-images | multipart的requestId与file，逐张上传；只接受本人目标文章范围。 |
| GET /media/comment-images/{imageId} | 校验认证、文章、评论及上传归属后返回真实图片；不复用游客图片读权限。 |

分页默认20、最大100，沿用严格正整数ID、未知/重复查询参数拒绝及稳定数据下确定顺序。根和回复数量应采用一致的已声明状态口径；删除占位、可见回复和隐藏项怎样计数需在文档及测试中一致。排序与跨请求offset快照限制明确，不承诺并发新增时固定快照。

## 5 数据、事务与审计

新增V6或实际下一个未占用迁移，不改V1—V5及演示迁移。建立评论、根/回复关联、创建回执、独立评论图片及引用，利用数据库约束落实归属、单次关联、唯一请求和合法状态。对文章/根线程分页及本人权属查询配置必要索引。

以最小改动扩展现有BusinessAudit及V5审计CHECK，保持旧审计行和原六类动作兼容。评论创建及本人删除与对应审计同事务，审计只保存内部标识、动作、状态/修订、结果和traceId，不存正文、图片字节、昵称或联系方式。无变化重试不重复生成成功变更审计。

并发新增、上传、删除及文章下架应有一致的锁顺序或等效事务控制；不能在目标已不可用后仍新增成功。不会把读取快照误称成永久授权；新图片读取每次重新判断当前状态。

原文章作者图片权限、不可变公开版本、草稿冲突、联系独立修订、实时关闭、日志脱敏及审计失败回滚都必须回归，避免为评论放宽公共认证过滤。
