## 2 点赞与取消

有效普通USER会话、ACTIVE账号及VALID校园认证方可操作。只能对当前公开且有有效公开版本的文章设置点赞或取消；目标不公开或未知统一404，先鉴权再查目标。账号后续认证失效时新操作被拒，历史已成功且未取消的点赞不因本批隐式规则自动重写；治理失效策略后续明确处理。

每个用户每篇文章只保留一份有效状态。PUT明确设置为已点赞，DELETE明确取消；相同设置重复或并发提交不增加次数、不反复递增修订，也不重复记成功变更。两个用户的各一次有效点赞计为2；取消只影响本人。不存在点赞时取消可以返回未点赞终态，不制造负数或虚假变更。

本人读者状态单设认证接口，不把liked/favorited或用户标识夹到游客列表和详情。公开数量可以在原文章count中展示，但不返回点赞用户明细、他人收藏和行为历史。

原本公开、无真实作者的DEMO文章也能测试真实点赞与收藏，不人为虚构作者或将其划为另一种用户权限。作者给本人文章点赞按普通用户相同规则处理；不要把“投币不自投”的约束擅自扩展为点赞禁令。

## 3 收藏与重访

认证用户可收藏当前公开文章，重复设置只保留一条有效收藏。本人收藏列表分页，按最近一次从未收藏变为已收藏的时间和文章ID确定次序；相同状态重试不刷时间。取消再收藏是新的有效收藏时间。

只有本人可读取自己的收藏和状态，不提供指定其他userId的读取/修改入口。文章下架、隐藏或删除后，收藏关系保留；列表仅返回articleId和统一不可用占位，不返回旧标题、摘要、正文、来源链接或具体治理理由。恢复可见时重新按当前公开版本读取，不使用旧快照泄漏内容。

本人可从不可用占位明确取消收藏，按自己的关系授权，不需要读取隐藏文章正文。取消收藏不删除文章、评论、举报或治理记录。此行为与点赞目标不可用时拒绝变更的规则在API中分别说明。

## 4 真实计数与历史演示数据衔接

当前article中effective_likes/effective_coins/count_origin包含早期固定DEMO数字，新作者文章为NONE/0；这些是旧阶段读取演示的合同，不能直接加到真实点赞上。

本批采用以下口径：

1. 新点赞状态表是实际点赞事实来源；公开effectiveLikes从未取消的成功记录聚合，或由有一致性核对的事务缓存得到，不能叠加旧演示值。
2. 保留原文章表内历史DEMO/NONE数字及来源数据，不通过清空、重置或改V1—V6来实现“归零”。优先在读取层使用明确的真实计数来源，旧字段仅作为历史演示记录，不能继续参与当前真实排序。
3. 原文章列表、详情及作者文章页的counts结构保留既有字段名称，新增实际来源枚举 `origin=LIVE`；本批有效获币为0，表示尚未实施投币和奖励，不将旧DEMO获币当真实贡献。LIVE用于标明本期实际互动统计，不表示钱包和荣誉已实现。
4. 内容sourceType仍独立保留FIRST_HAND/CURATED/DEMO；DEMO内容下的真实测试点赞不自动变成虚假模拟计数。演示内容仍明确为演示。
5. 认可排序使用上述实际获币（本批0）、实际点赞、首发时间、稳定文章ID依次降序；最新排序不受收藏、点赞或取消影响。组合筛选先于排序，分页及筛选合同保持。
6. 游客接口只增加真实统计语义，不增加受限身份字段。记录这一明确的计数来源/排序合同变化，更新API、演示说明、受影响测试及前端交接，不能把旧阶段原始报告改成“当时已经LIVE”。

查询应使用批量聚合/索引或等效方案，避免每篇文章逐条查点赞造成N+1。若选择冗余计数，事实状态、计数和审计必须同事务，且需验证并发及失败回滚；不能为了展示数量编造真实记录。旧演示存储值、文章内容和已有业务数据仍须核对保留。

## 5 接口契约草案

统一 `/api/v1` 及原成功/失败包、traceId。写操作使用明确目标状态而非toggle，避免网络重试翻转结果。最终空请求体约定和字段在API及Postman同步，拒绝额外userId/role等身份控制字段。

| 接口 | 行为 |
| --- | --- |
| PUT /articles/{articleId}/like | 认证本人设置已点赞；返回articleId、liked及真实有效点赞总数；重复已点赞无变化。 |
| DELETE /articles/{articleId}/like | 认证本人取消；返回未点赞状态和真实总数；目标须仍公开。 |
| PUT /articles/{articleId}/favorite | 认证本人收藏当前公开文章；返回articleId、favorited，不公开他人收藏数量。 |
| DELETE /articles/{articleId}/favorite | 认证本人取消，包括自己已收藏但现不可用的文章；不返回隐藏内容。 |
| GET /articles/{articleId}/interaction-state | 认证本人读取当前公开文章的liked/favorited，不返回其他用户状态；目标不可用404。 |
| GET /me/favorites?page=1&size=20 | 本人收藏分页，公开文章返回当前摘要，不可用文章只给最小占位；默认20、最大100。 |

新增受限接口和失败no-store，不能仅靠前端隐藏。游客原文章接口仍免费可读，counts为实际公开聚合，无私有读者状态。严格正整数ID、分页、未知/重复参数及不支持方法处理沿用原风格。不存在关系的取消与状态读取不能顺带创建账号或关系。

## 6 数据、审计与日志

新增V7或实际下一个未占用迁移，不改历史V1—V6/DEMO迁移。建议独立点赞和收藏状态表，以(user_id,article_id)唯一约束落实一次有效状态，保存必要状态、修订及时间，并支持文章点赞聚合与本人收藏分页。

真实状态变化接入原事务审计及安全日志，已有审计动作/状态CHECK在新迁移中兼容扩展，保留旧行。重复相同状态不记新的成功变更；新事务失败时状态、必要计数及审计一起回滚。日志不记录正文、邮箱、会话或用户收藏内容快照。

新增动作、模块、阶段、内部对象及修订接入第六阶段debug/release机制和文件白名单；模式切换不改变点赞、收藏及权限。验证并发请求、延迟提交、MDC清理与trace准确关联，避免把无变化或回滚说成新增成功。

操作与文章下架并发时按一致锁序或等效事务规则核查可见性，不在目标已终结后悄悄新增成功。本人取消不可用收藏按私有关系处理，仍保持当前账号权限检查。
