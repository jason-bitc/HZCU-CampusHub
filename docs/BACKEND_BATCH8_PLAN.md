## 2 已确认的规则参数

| 参数 | 当前值及业务含义 |
| --- | --- |
| 登录奖励 | 有效认证用户每日可领取2币，最多1次；成功登录形成资格，领取由独立接口完成，不改旧登录响应合同 |
| 阅读奖励 | 阅读公开文章满180秒可领取1币，全账号每天最多1次，不是每篇每天1次 |
| 每日奖励总量 | 当前两项合计最多3币；分别展示任务状态、可领取条件及当日剩余额度 |
| 业务日期 | Asia/Shanghai；采用服务端时钟，不能由客户端提交日期、币数或已完成标志决定奖励 |
| 每篇投币上限 | 同一用户向同一文章累计最多2币，跨日期及文章编辑/重新发布不重置 |
| 投币数 | 每次为严格正整数，可投1或2币且累计不超2；拒绝0、负数、小数、溢出及非法格式 |
| 撤回 | 本批不提供读者自行撤回、取消投币或任意返币接口 |
| 非现金 | 无购买、充值、提现、现金兑换；无付费文章和咨询订单 |

上述额度和时长通过服务端配置提供，启动时校验。规则说明接口返回当前生效值；成功事件保存适用业务日期与规则参数/版本，后续改配置不重写旧账、不使当日已领记录重新可领。正式治理修正与撤回返还策略后续单独确认。

本次关闭OP04当前实施参数；OP05中的单篇额度和用户撤回已确认，治理失效及返还仍保留；OP06完整荣誉表留待下一阶段，不猜测等级和门槛。

## 3 简单阅读奖励

认证用户进入当前公开文章后，调用阅读开始接口。服务端保存本人、文章、开始时刻和业务日期，返回可领取时刻；同账号、文章和当日重复开始返回原计时，不刷新开始时间或产生重复记录。

满180秒后可提交领取。只按服务端开始记录和经过时间判断，不接受客户端宣称已读满的数值；不做心跳、滚动轨迹、前台停留监测、答题或设备指纹。该规则是简单计时资格，不声称证明了实际专注阅读。本人文章和无真实作者的公开DEMO文章可阅读，不额外增加禁止自读的奖励规则。

开始与首次领取均要求文章当前公开且具有有效公开版本；跨业务日须重新开始当日计时，不把昨日未领取资格挪到今日。多篇文章、多设备或不同requestId并发领取，共用本人当日一次阅读额度。重启不丢失已开始计时或已领记录；计时及日期边界使用可注入Clock验证，生产环境不提供任意改钟入口。

## 4 钱包、账本与有效贡献

初始可消费余额为0，不能从旧DEMO字段初始化币。奖励增加本人可消费余额；投币扣除读者余额，并为目标文章和真实作者记录等额有效贡献。作者的获币贡献与可消费钱包分离，收到贡献不再额外铸造成可消费币，作者消费自己的奖励币也不降低已收贡献。

本人可查询余额、稳定分页的获得/支出账本及本人收到的贡献汇总。每笔成功变动可追溯到唯一业务事件、日期和关联文章；查询他人账本、投币者名单及真实邮箱不开放。文章后来不可用时，私人历史仅保留必要标识和数字，不复制或返回隐藏标题、正文、作者联系方式及治理原因。

成功奖励、投币事实和原始账目不得通过直接改数或删除来抹除。有效贡献的未来治理状态须可扩展，但本批不偷偷提供管理修正接口。没有已实现治理失效时不宣称已有扣回、恢复和反作弊裁定能力。

## 5 投币、幂等与事务

沿用有效普通USER会话、ACTIVE账号和VALID校园认证。先鉴权，再解析并验证业务输入；目标须当前公开、有有效公开版本、有真实关联作者且不是本人文章。旧无真实作者的DEMO文章仍可阅读/点赞/收藏，但不能接收投币；不替其伪造作者。已有真实作者的文章按相同规则处理，不单凭正文sourceType决定资格。

奖励领取和投币使用小写UUID requestId及持久成功回执。同一用户、动作、requestId和相同业务内容的重复/并发重试，至多一次生效；已成功请求跨午夜或重启重放仍返回原回执，不再扣发。同一键改文章、金额或阅读会话返回409 REQUEST_KEY_REUSED。另以账号/任务/业务日期唯一性控制奖励额度，以账号/文章累计事实控制投币上限，不能换requestId绕过。

幂等历史回执先经当前身份认证，仅返回本人原事件的最小数据；文章之后不可用时不通过回执带出正文。已提交事件的balanceAfter是当时余额，不冒充当前余额，页面应以本人余额接口刷新。失败未提交的请求不留下成功回执，可按相同请求重试；不同键重复已领取任务的终态及错误码在最终API明确说明。

余额、奖励/投币事件、支出账目、作者及文章有效贡献和成功业务审计同事务提交。若以事实表聚合贡献，可不维护重复累计列；任何冗余余额/累计必须能与事实核对。账本、审计或其他必需写入失败全部回滚，不留下已扣余额但无贡献等部分成功。

并发必须同时验证同一账号向不同文章支出、同一账号同篇限额、多人向一篇投币、领取与支出交错。采用明确的锁顺序、唯一约束、余额及额度条件更新或等效方案，不靠应用内锁。与文章撤回并发时按文章锁的提交顺序判定；撤回先提交则新投币失败，成功投币后下架不自动返还或清除历史贡献。后续恢复公开读取同一事实。

## 6 读取、排序与前端契约

公开列表、详情、作者文章及可用收藏摘要统一保持counts.origin=LIVE，effectiveCoins改为该文章已提交有效投币之和，effectiveLikes仍来自active点赞事实。认可排序依次为真实有效获币、真实点赞、首发时间、文章ID降序；最新排序和组合筛选不变。

保留旧article.effective_coins/effective_likes/count_origin、旧内容和迁移，不混算旧DEMO数字。无真实投币时effectiveCoins为0。查询采用批量聚合或等效方案，不逐篇查币或点赞。游客只有公开聚合，不新增本人余额、投币记录或他人身份字段。

以下为开发契约起点，实施者需按现有路由和输入约定确定最终字段并同步Postman；改变下列业务语义须回报本规划对话。

| 接口 | 目的与关键约束 |
| --- | --- |
| GET /me/coins | 本人当前可用余额与有效获币贡献，明确二者含义 |
| GET /me/coin-ledger?page=1&size=20 | 本人稳定分页账本；默认20，上限100，无他人userId参数 |
| GET /me/rewards | 当日规则、登录/阅读任务状态、当日剩余额度与服务端时间 |
| POST /me/rewards/login | requestId；领取当日登录2币 |
| POST /articles/{id}/reading-session | 空请求体；开始或返回本人当日该文章的原计时资格 |
| POST /me/rewards/reading | sessionId、requestId；满180秒领取当日一次1币 |
| GET /articles/{id}/coin-state | 认证本人已投数、单篇剩余额度与目标可投资格，不暴露他人行为 |
| POST /articles/{id}/coins | amount、requestId；原子投币，返回本人成功事件回执 |

沿用code/data/traceId、正确HTTP状态及no-store。未知/重复字段、额外身份控制参数、非法分页、过大或不支持正文要拒绝。余额不足、过早领取、超额度、自投、无真实作者等给出固定业务码和可理解信息；未知及不公开文章仍按404隔离。GET不因查询而发放奖励或改变余额。

## 7 数据、日志与交付保护

新增V8或实施时实际下一个Flyway迁移；V1—V7逐文件SHA保持。账本/回执、阅读资格、每日领取及投币事实建立必要约束和索引。沿用MySQL，不引入H2冒充集成验证，不为小批量业务增加Redis、队列或支付系统。

新动作真正接入现有安全日志白名单、请求traceId、事务COMMIT/ROLLBACK及Debug代码诊断。默认Release；两模式业务结果一致，Release不输出调试细节。金额/余额等只按允许的最小字段记录，邮箱、密码、验证码、Bearer、请求正文和私人完整账本不进日志。成功事件以提交后回调记录，审计写失败不可假成功。

仅在campushub_test、随机身份、受控邮件及隔离文件中自动验证；不外发真实验证码、不清库、不改本人开发资料。原有未提交报告、设计和工具保持。交付API与规则说明、Postman、迁移、测试、日志覆盖、实际验证记录、实施记录及本批追踪表；前端页面和真机另行对接。
