## 本批业务范围

1. 本人资料：昵称、专业、当前在校或毕业阶段及可选简介；邮箱、认证状态、角色不由资料接口修改。默认昵称采用不含邮箱或学号的普通昵称，专业允许暂缺，发文时再选择文章适用专业。当前阶段与文章中的经历阶段分开。
2. 草稿：可维护多篇独立草稿，未写完的标题、正文和标签允许保存；读取最后确认保存的草稿。每次保存带期望修订号，过期修订返回409，不静默覆盖。保留Markdown原文和图片、来源关系，为两端共享内容提供基础。
3. 图片：认证作者为本人文章上传图片，返回稳定图片标识及URL。一次上传一张，客户端请求标识用于重试去重；同标识不同文件拒绝。文章不设固定业务图片张数上限。失败不能显示上传成功或丢掉已有草稿。
4. 发布：标题、可读正文或有效图片、至少一个岗位和专业、明确的经历阶段与来源类别在发布前确认。公司、当时基础、简介、写作提示可跳过；摘要不填可由正文生成。来源沿用FIRST_HAND/CURATED/DEMO，不把演示或整理自动记作亲历。
5. 发布后编辑：以独立草稿修改，公开版本在作者确认再次发布前保持不变。一次发布原子地生成不可变公开版本并更新公开指针；重复提交不生成多篇文章或重复版本。草稿保存不生成无限的公开历史版本。
6. 文章管理：本人文章列表、草稿读取、发布、自主下架、自主下架后的恢复及软删除。管理员隐藏内容不能被作者重新发布或恢复，删除状态不能再编辑或公开。恢复保留原首发时间，修改后的正文记录更新时间。

作者公开主页、站外联系、评论、点赞、投币、收藏、荣誉、管理员治理和运维操作留在后续批次；本批本人资料不对访客开放。

## 接口与数据约定

所有JSON接口沿用`/api/v1`及`code/data/traceId`，错误使用已有失败结构和正确HTTP状态码。

| 接口 | 本批行为 |
| --- | --- |
| GET /me/profile、PUT /me/profile | 本人基础资料读取与修改，修改带修订号 |
| POST /me/articles | 创建独立空草稿，客户端创建请求标识实现重试去重 |
| GET /me/articles | 本人文章及草稿分页；默认20、最大100，确定排序 |
| GET /me/articles/{id}/draft、PUT /me/articles/{id}/draft | 获取与完整保存本人草稿，保存带expectedRevision |
| POST /me/articles/{id}/publish | 带expectedRevision和发布请求标识，校验后原子发布 |
| POST /me/articles/{id}/unpublish、POST /me/articles/{id}/restore | 本人自主下架与恢复，不能越过管理员隐藏状态 |
| DELETE /me/articles/{id} | 本人软删除，重复删除结果一致 |
| POST /me/articles/{id}/images | multipart上传本人文章图片，携带独立客户端上传标识 |
| GET /media/images/{imageId} | 按内容可见性返回图片二进制及安全响应头 |

- 资料及文章写操作使用服务器当前有效身份确定作者，不接受客户端传入作者、认证或角色控制字段。所有本人接口检查权属，访问他人草稿和文章管理目标统一404。
- 校园认证失效、账号受限、会话退出或到期立即作用于新写请求。公开文章仍可游客阅读；读取JSON不因新增作者关联而泄漏邮箱、身份资料或联系信息。
- 作者归属是新增的真实账号关联。旧演示文章不批量绑定给王晨或虚构真实作者。新文章互动计数为零且来源为NONE，旧固定演示计数仍为DEMO；更新读取合同及约束，避免把未实现互动称为真实获币。
- 岗位、专业、公司、主题继续使用现有分类标识，不能把客户端自填名称直接当作有效分类。文章专业可以默认本人专业，但服务端仍需显式记录文章背景；不以当前年级代替经历阶段。
- 正文统一保存原始Markdown，完整保存请求不能悄悄转换为HTML或丢弃复杂结构。移动端遇到不能安全编辑的正文时保留原文并说明限制，相关前端实现后续验证。
- 发布使用独立不可变公开版本；已发布文章的草稿编辑不影响公开正文、标签、资料链接或图片访问。首次发布时间用于最新排序，重发、恢复不冒充首次分享，更新信息另列。
- 使用新增Flyway迁移，不修改V1/V2/V3文件；保留原文章和用户数据。资料、草稿、分类、来源链接、图片引用与发布结果的一致性需有事务保证。数据库或文件失败时不留下假成功。

## 图片与存储默认参数

以下是本批可配置技术默认值，记录为待需求/设计评审核对的参数，不能表述为教师已经批准。

| 项目 | 默认值与要求 |
| --- | --- |
| 图片格式 | JPEG/JPG、PNG；核对实际文件内容，拒绝伪装类型及SVG等可执行内容 |
| 单文件大小 | 不超过10MiB，multipart总请求12MiB；逐张上传，不限制文章图片总张数 |
| 图片尺寸 | 不超过2500万像素，验证维度及文件有效性，避免仅凭扩展名认定成功 |
| 正文大小 | Markdown UTF-8不超过1MiB，JSON请求不超过2MiB；不设置最低字数 |
| 存储 | 默认server/.local-data/media，可配置到本机目录；测试采用独立运行目录，实际文件不入Git |
| 路径 | 服务端生成存储键，拒绝路径穿越；不以用户文件名或URL决定本机访问路径 |

- 图片引用必须属于本人对应文章，保存时建立可核查的版本引用；解析Markdown引用应理解结构，不用简单全局正则破坏代码片段或正文。
- 只有当前公开版本引用的图片允许游客读取。未公开、已移除、下架、隐藏或删除内容的图片不能经旧链接继续公开访问；有效作者可按权限预览自己的非删除内容，其他用户不能猜图片标识读取。
- 本机私有图片预览使用带身份的下载或Blob方式，不把Bearer令牌写入URL；在接口文档中交代WorkBuddy后续对接方法。公开与私有图片均采用避免旧缓存绕过状态核验的响应策略。
- 未引用文件的长期清理策略与完整备份后续设计。上传/事务失败只清理本操作创建的临时文件，清理前确认解析路径在指定存储目录内，不删除原有图片或其他项目文件。
- 原资料链接仅保存来源说明及HTTP/HTTPS地址，后端不主动抓取外站或网盘内容。
