# JMeter 正常负载执行说明

适用于《系统测试计划》V2.3 §4.3 和 TC-NFR04。模板采用 JMeter 5.6.3 计划格式和 Groovy 采样器，目标固定为本机隔离业务入口 127.0.0.1:8082。正式执行时记录实际 JMeter、Java 与候选构建版本。

## 1 准备数据与配置

1. 按计划复位 ENV-02 的专用测试库和媒体。校验 200 个合成用户、2,000 篇合成文章、5,000 条初始评论，保存种子或导入清单和快照摘要。
2. 在 Git 忽略的本机目录准备 UTF-8 JSON 作为输入。顶层包含 publicArticleIds、listQuery 和 writers。前两项分别是已通过预检的公开文章 ID 数组，以及不带问号、已经 URL 编码的固定查询参数串，可留空。
3. writers 必须恰好有 30 项。每项填入 token、draftId、draftBody。各 token 来自不同的有效认证合成账号，各 draftId 是其所有且互不相同的专用草稿。draftBody 使用候选版保存草稿接口的实际请求体，包含 expectedRevision、title、summary、body、jobIds、majorIds、companyIds、topicIds、experienceStage、sourceType、sourceNote、sourceLinks。先读取对应草稿，按其当前修订与合法字段生成请求体。
4. 正式计时前分别验证列表、公开详情、保存草稿与发表评论能够成功。完成预检后复位数据。若复位影响会话或草稿修订，重新取得会话和修订并更新输入。凭据和输入 JSON 保存在本机，不纳入共享目录。

## 2 执行与结果

将模板复制为 .jmx 后，用 JMeter 非 GUI 模式执行。替换示例路径为本机独占目录。设置保留时间戳、耗时、标签、响应状态及成败，日志和采样结果不得保存请求头、令牌或响应正文。

    jmeter -n -t G04-normal.jmx -Jg04.confirm=ENV-02 -Jg04.input=isolated-fixtures.json -l G04-normal.jtl -j G04-jmeter.log

线程组为 30 并发、60 秒升载、总时长 660 秒。使用实际负载起点切分稳态窗，使用请求开始时间筛选 60 秒升载后的 600 秒。按 READ_LIST、READ_DETAIL、WRITE_DRAFT、WRITE_COMMENT 统计请求与成功样本，输出读写 P95、吞吐、非预期错误率和实际比例。各线程以不同的操作槽起步，完整循环内请求比例为 40:40:10:10。稳态窗口受截断和接口耗时影响，必须报告实际比例。出现 SETUP_INVALID 时按暂停流程先修正环境或输入。

保留候选提交、环境记录、合成数据起点及参数摘要、模板与生效配置、原始 JTL、JMeter 日志和资源趋势；按计划 §7 检查阈值、错误和是否具备验收条件。阶梯压力、稳定性与降载恢复参数见 §4.3，分别记录实际脚本和原始样本。

JMeter 执行依据见 [Apache JMeter 使用手册](https://jmeter.apache.org/usermanual/get-started.html)。
