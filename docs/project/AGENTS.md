# 正式文档更新规则

1. 本目录为共享文档唯一编辑入口。`deliverables`是本机历史导出，禁止继续只改交付包而漏同步此目录。
2. 先核对当前Git分支、工作区、远端及本次允许修改的文件。使用`docs/wc-任务名`或`docs/ljh-任务名`等个人任务分支。已有脏代码时使用独立工作树，不切换丢弃或自动暂存用户工作。
3. 用户要求后续文档更新同步GitHub。完成一轮文档修订、格式同步和检查后，默认提交并推送本次个人文档分支；任务若明确禁止提交或推送，以当轮用户约束为准。没有网络或权限时保留成果并准确报告，不能宣称已同步。
4. Word、PDF、Markdown及引用版本共同维护；可编辑图、WBS、MPP与展示图在受影响时共同更新。导出PDF后检查本轮修改页面、目录页码和跳转，不能用刷新哈希代替内容、模型或排版检查。
5. 记录真实会议、实际工作与用户反馈。计划、历史测试、网络调研和本轮验证分别说明，不虚构访谈、实际人时、成绩分项或完成日期。
6. 执行`Sync-ProjectDocs.ps1 -Commit -Push -Message ...`前查看本次相关变化。脚本不强推、不合并main；若暂存区已有其他内容，应先报告并隔离，不自动清空。
7. 在GitHub创建或更新本任务PR，另一位成员复核后由组长协调合并。接入Git不代表两人已完成评审，不自动代另一人批准。
8. 仅提交本组文档、模型、原型及必要制作源。实际密码、授权码、数据库导出、运行日志、录制视频、旧ZIP和原始教材课件不进入共享文档目录。
