# 城院帮演示文章调研计划

这批文章服务于准备投递和面试的大学生，重点回答“起点和我差不多的人，从准备到拿到结果，中间具体做了什么”。组内以同一批完整 Markdown 正文演示原生微信小程序阅读、网页阅读和作者创作。正文经复核后进入项目，运行环境通过现有文章接口读取。

## 1 文章选题

首批目标为 12 篇，可按证据调整具体公司和经历阶段。优先覆盖杭州和大学生实习，同时扩大岗位及专业背景。前九篇覆盖岗位与准备路径，后三篇覆盖失败、选择和可立即使用的工具型内容。栏目是调研和演示组织方式，入库时按已有岗位、专业、公司、主题字段映射。

| 编号 | 类型与选题 | 完整正文应有的信息 | 优先核对 |
| --- | --- | --- | --- |
| A01 | 第一份实习长文｜Java 后端从准备到投递 | 起点、时间线、项目、简历、投递、笔试面试、结果、检查清单 | S14、S23 提供线索，逐条确认阶段及经历归属 |
| A02 | 公司面试流程｜C++ 后端实习 | 岗位、作者起点、公开笔试面试环节、被问到的知识和应对、个人结果与信息日期 | S16；杭州公司或岗位地点有公开证据时注明 |
| A03 | 项目复盘｜Web 前端实习项目如何准备和讲述 | 项目起点、本人贡献、取舍、面试追问、改进、可复用清单 | S17、S18 |
| A04 | 岗位准备｜测试开发实习 | 测试开发与软件测试的职责边界、样例测试任务、准备、面试流程、案例局限 | S15；若补到纯软件测试样本，明确标为另一个岗位 |
| A05 | 岗位准备｜运维／SRE 实习 | Linux、日志和监控基础，如何用项目说明排障过程，面试准备和常见误区 | S19；用公开资料支持通用知识点 |
| A06 | 面试复盘｜Android 移动开发实习 | 作品准备、客户端与接口联调、面试轮次、经验可迁移的范围 | S20；不同技术栈分别标注 |
| A07 | 跨专业路径｜数据分析实习准备 | 适合的起点、表格和 SQL 入门、公开数据练习、成果表达、投递前检查 | 补查公开岗位说明、可靠工具文档及可核验案例 |
| A08 | 跨专业路径｜产品助理实习准备 | 职责、需求分析和基础原型作品、面试讨论、可执行的准备步骤 | 补查公司公开岗位说明与大学生准备材料 |
| A09 | 跨专业路径｜电商运营实习准备 | 工作职责、指标与活动复盘、作品材料、面试看什么、什么信息需自行确认 | 补查公开岗位说明与可信学习材料 |
| A10 | 失败复盘｜Java 后端一轮面试后的调整 | 准备方式、遇到的追问、结果自述、下一轮改善和读者可迁移做法 | S21；岗位与 A01 相同，结论有所区别 |
| A11 | 求职选择｜多个机会怎样比较 | 时间限制、岗位内容、带教、通勤、选择依据，以及信息不足时可向招聘方确认的问题 | S18、S24；样本各自说明，岗位与企业细节归属清楚 |
| A12 | 实用短篇｜第一次投递前的检查清单 | 投递前、投递后与面试前的明确动作，含可复制的记录示例 | 校就业服务或企业官方招聘指南；适用于多个岗位 |

A01 为 1,800–2,600 字长文，至少 7 个正文二级标题并设三级小节。A02、A03 等案例类约 800–1,500 字，A12 约 450–800 字，均以读者能直接使用为完成标准。A07–A09 缺少可核验亲历时，按可信公开资料写成完整的岗位准备指南，显式说明取材范围。涉及面试未通过、等待结果或作者自行拒绝机会，按原来源标记。

## 2 调研与写作顺序

1. 回查既有的 S01–S25 来源和待复核条目，先确认链接、正文可读性、发表或经历日期、身份及结论分别有哪些证据。沿用旧来源编号，新增合格来源另编号。
2. 补查 A07–A09 和缺少的来源。公开亲历优先看原作者帖子、博客、可实际播放的视频或官方文字稿。岗位职责、学校服务和工具说明用公司、学校或项目的官方资料。牛客、力扣中国站、技术博客、B 站、抖音、X 和 YouTube 都可作为候选渠道。
3. 先写 A01、A03、A12，校对长文、图文、短文三种结构，再按同一格式完成其余选题。每篇保留清楚的起点、过程和可采取的下一步。整理多条经历时分别归属，经验细节和建议分别写。
4. 复查断链、主张与来源、内容重复、作品归属、图片授权、个人隐私和标题的可检索性。证据不足的选题在覆盖记录里标明已查范围和原因。

公开帖子只能归为来源作者自述。项目整理文章使用 `CURATED`，署名“城院帮资料整理”，显式呈现链接和适用边界。只有直接投稿且授权明确时才可使用 `FIRST_HAND`。无法证实学校、专业、实习结果或雇佣关系时留空或说明来源局限。本校经历按已核实的本校资料填写。舞弊、承诺保录、培训销售、标题党、招聘广告或仅有标题／截图的内容列入排除或待核验记录。外部图文使用独立归纳与可核验来源，组内可发布的原创图和授权图才随文入库。

## 3 项目收录位置和格式

```text
docs/project/meetings-research/演示文章/
  README.md
  豆包调研提示词.md
  articles/A01-文章短标题.md
  assets/A01/图名.png
  article-index.json
  sources.csv
  coverage.md
```

每篇 `.md` 是从开头到结尾的完整正文。文章标题和摘要写入索引，正文从引言开始，用 `##` 和 `###` 分节。索引逐篇记录 `id/file/title/summary/jobTags/majorTags/companyTags/topicTags/experienceStage/sourceType/sourceNote/sourceLinks/sourceIds/assets`。标签用名称，`sourceLinks` 为 `[{ "label": "...", "url": "https://..." }]`，公司为空时用 `[]`。岗位性质、当时基础和时间背景写入正文，不依赖新接口字段。

来源表保留 `sourceId,title,platform,url,publishedAt,accessedAt,readScope,verifiedFacts,limits,decision,usedBy`。视频记录实际核对的时间段或所用文字稿。图片用 PNG 或 JPEG，附替代文字与来源。库内正文用相对路径链接本地图片，导入时通过现有作者上传接口逐篇上传，并换成该文章返回的媒体地址。

## 4 双端与作者演示

| 场景 | 使用文章 | 检查内容 |
| --- | --- | --- |
| 小程序发现与阅读 | A01、A02、A10、A12 | 标题和摘要搜索，同岗位不同结果，公司与专业组合筛选，无公司文章可用。长文目录和锚点可跳转，最后一节可读，来源链接可复制。 |
| 网页发现与阅读 | A01、A03、A07、A12 | 与小程序的标题、摘要、标签和正文一致。长正文中的嵌套列表、引用、本地图片及链接在各屏宽可读。 |
| 小程序作者创作 | 以 A03 正文作一份项目整理草稿 | 保存并重新打开草稿，上传 JPG 或 PNG、调整位置和替代文字、预览后发布。 |
| 网页作者编辑与工作区 | 以 A01 正文作修订稿 | Markdown 编辑与预览、双端草稿恢复、通过原修订号验证冲突、重新发布后双端均读取新公开版本。发布前草稿改动对访客保持私有。 |
| 同专业与跨专业阅读 | A01、A04、A07–A09 | 用独立演示账号切换专业，核对认证同专业快捷筛选和手动专业筛选。项目标签服务于读者检索，来源作者的真实专业只按已有证据描述。 |

作者测试使用隔离环境和项目演示账号。素材库验收后再将通过复核的正文通过现有创作接口导入演示库。小程序和网页指向同一后端数据，不分别维护正文。点赞、投币、评论、认证身份和草稿状态由演示操作产生。现有固定回归种子继续用于自动化验证。

入库前逐篇核对索引、来源编号和图片都能定位。检查 A01 足够长且最后一节完整，A03 有可随库分发的图片，A12 的清单可以直接用。须有同一岗位多篇、公司有值及为空、多个专业方向。默认由执行调研的一方交齐全文和索引，由组内复核后保存并导入。
