# 豆包调研提示词

你负责为城院帮调研并写作首批完整的实习与求职文章。面向已在准备投递和面试的大学生，重点说明与他们基础相近的人怎么准备第一份实习，遇到难点如何调整。文章供微信小程序和网页阅读、搜索筛选及作者创作调试。请逐篇写出可直接阅读的正文，另附逐篇索引和可追溯的来源。开工前先读同目录《城院帮演示文章调研计划》与随附的既有调研。旧的 S01–S25 是线索，使用前重新核验。

## 选题和顺序

- A01 Java 后端第一份实习准备与投递时间线，覆盖项目、简历、投递、笔试、面试、结果和检查清单，1,800–2,600 字，至少七个二级标题并设三级小节。
- A02 C++ 后端实习面试流程，聚焦岗位、面试环节、准备与结果。
- A03 Web 前端实习项目复盘，用组内可分发的原创或授权图，正文说明项目取舍和面试追问。
- A04 测试开发实习准备，明确测试开发与软件测试的职责边界。
- A05 运维／SRE 实习准备，从日志和监控切入，说明面试中的项目表达。
- A06 Android 移动开发实习面试复盘，突出准备、联调与工程实践。
- A07 数据分析、A08 产品助理、A09 电商运营，分别写一篇面向跨专业读者的岗位准备指南。找不到合格亲历时，使用可核对的公开岗位说明、学校资料或官方工具文档。
- A10 Java 后端失败复盘，说明哪里准备不足、后来如何调整。A11 多个机会的比较与选择，写清作者当时有哪些信息，等待或未知结论按原文标记。
- A12 第一次投递前的可执行清单，450–800 字，适用于多个岗位。

A02–A11 通常约 800–1,500 字。先交 A01、A03、A12 做内部结构校对，然后继续完成全部成稿。每篇先说明适用的读者和起点，再交代日期或时间线、行动、结果或已知边界，最后给出读者能用的下一步。至少有同一岗位两篇、多个专业方向、带公司和无公司的文章。技术例子用简短代码或具体步骤。正文结构优先采用标题、段落、列表、引用、代码、图片和链接。

## 来源和写作要求

1. 先看牛客、力扣中国站、原创技术博客和官方资料，再查 B 站、抖音、X、YouTube 等。优先大学生首份实习，杭州为优先线索，2025–2026 年亲历优先。引用早期材料时注明年份，用于长期适用的经验或知识。无需为了覆盖平台勉强收录。
2. 实际打开原文，核对作者自述、公司、岗位、发布日期与经历日期。官方招聘信息只能支持公告所覆盖的事实。视频实际核对的片段记时间段，只有标题、摘要或不可核对字幕时作为待查线索。
3. 排除标题党、培训机构引流、纯招聘广告、只晒录用结果、鼓励造假和无法核验的转述。保留通过、拒绝、失败、等待等真实结果的区别。一个作者的面试结果只代表该次经历；公司或岗位情况注明记录时点和适用范围。
4. 用独立中文写作，按匿名或公开来源如实归因。来源作者与项目整理署名分别处理。外校案例按来源披露的学校或地区据实描述，身份未披露时留空。本校亲历以明确来源为前提。避免收录个人联系方式、简历截图、内部面试材料、可识别头像和私密链接。
5. 常规成稿用 `CURATED`，署名“城院帮资料整理”。`FIRST_HAND` 仅用于有发布授权的直接投稿。真实公司标签来自可核对的上下文；个别负面感受应作为自述、说明范围，必要时匿名。少量关键引用可以有清楚出处，完整本文写成独立的整理文章。
6. 每篇标明正文中的关键事实由哪些来源支持，建议和推断写明依据。证据不足的亲历保留在待核验表，有可靠资料可转写为完整的岗位指南。日期、身份、薪资、结果和未确认的数字不作推测。

## 交付格式

优先交付以下文件。如果你的环境只能生成可下载文件，按相同的目录和文件名交付，由项目组将它们放入 `docs/project/meetings-research/演示文章/`。

- `articles/A01-文章短标题.md` 至其余编号各一篇。文件只有可阅读的正文，文章标题、摘要、标签及来源元数据放索引。正文内按 `##` 和 `###` 分节，末尾保留可执行小结。正文中的本地图片使用 `../assets/Axx/文件名.png` 并附替代文字。
- `article-index.json` 是一个文章数组，每项包含 `id/file/title/summary/jobTags/majorTags/companyTags/topicTags/experienceStage/sourceType/sourceNote/sourceLinks/sourceIds/assets`。路径相对此目录，三个字段 `jobTags`、`majorTags`、`topicTags` 填本篇适合的分类名称，未知或未使用的公司标签为 `[]`。`sourceLinks` 的每项用 `{"label":"来源名","url":"https://..."}`。资产每项写 `path/alt/licenseOrProvenance`。标签用可映射名称，实际分类 ID 由项目组导入时匹配。
- `sources.csv` 以 UTF-8 编码输出。列为 `sourceId,title,platform,url,publishedAt,accessedAt,readScope,verifiedFacts,limits,decision,usedBy`。`decision` 使用“采用”“待核验”“排除”。既有编号保持一致，追加来源使用未被占用的编号。
- `coverage.md` 写实际完成篇目、主要岗位和专业覆盖、待核验缺口，以及 A01 的长文目录、A03 的可分发插图和 A12 的短篇检查结果。只对实际完成并已核对的交付物标记通过。
- `assets/Axx/` 只放随文可合法分发的 PNG／JPEG。优先自己绘制流程、时间线或面试前检查图，标注资料来源。正文里需要跳转的外链使用公开、持久的原文入口。

收尾时逐篇重新打开成稿，从标题和摘要推到正文最后一节，检查对应来源、图片、时间、结果和分类能否定位。输出文件清单和真实缺口。
