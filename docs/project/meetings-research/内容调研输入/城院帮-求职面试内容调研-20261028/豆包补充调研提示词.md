# 豆包补充调研提示词

请为G04课程项目“城院帮”开展求职与面试经验调研。平台面向校园学生，首批内容集中计算机相关专业，服务已经确定目标岗位、正在准备投递和面试的人。调研结果用于uni-app小程序及网页的内容结构、文案和页面设计。

请先阅读随附的来源台账与调研报告，避免重复收集。优先补充2025至2026年第一份实习的准备过程、投递复盘、面试失败后的调整、项目表达、入职后的经历和选择实习时的实际考量。岗位覆盖Java后端、前端、软件测试或测试开发，兼顾普通企业与中小团队。真实的本校案例优先，找不到时直接说明，不把外校案例改成本校故事。

优先查B站、抖音及小红书的个人亲历，能够追到原作者时也可用牛客、个人博客、X与YouTube。海外经历保留国家地区与岗位语境，不能直接套作国内招聘规则。

请先筛选约20条线索，再保留8至12条内容足够具体的材料。数量不足时提交实际找到的结果，不通过机构文章、转载和虚构内容凑数。

排除培训机构和求职服务引流，尤其是课程、付费群、资料包口令、学员案例、保offer、付费内推、实习证明购买和伪装亲历的模拟面试。作者在正文提到用过某个公开学习资源，不单独视为营销；需要判断发布主体、正文的商业目的和引流方式。平台自己的广告与作者正文分开判断。

标题夸张、只晒offer或只说收入而没有过程的材料不作为核心样本。真实原帖也要检查内容是否具体、时间是否明确、是否存在套话或互相矛盾的细节。看不清背景和结果时保持缺项，不替作者补出学校、专业、年级、薪资或录用。

每条材料请输出以下信息，并提供能直达原帖或原视频的链接，不使用搜索结果页作为出处。

| 字段 | 记录要求 |
| --- | --- |
| 编号、原题、平台、原作者 | 转发者与原作者分开 |
| 发布日期、经历日期、后续更新日期 | 不把最近抓取时间写成面试时间 |
| 岗位、公司或团队、地区 | 保留原文粒度，不脑补 |
| 当时基础、专业、阶段、已有经历 | 只记录作者明确说过的部分 |
| 核心经过 | 准备、投递、面试、调整及结果，能查到多少写多少 |
| 提取程度 | 全文已读、字幕已读、视频已看、仅简介、无法访问，分别标明 |
| 视频证据 | 写清字幕来源与具体时间段；没有播放或字幕就不填写虚构时间点 |
| 商业审查 | 是否出现课程、付费群、内推、模拟学员或外部联系引流；写出判断依据 |
| 可用于设计的内容 | 独立概括50至100字，并提一个读者自然会追问的问题 |
| 局限 | 个人自述、岗位地区限制、过时或缺失信息 |

请把已知待复核条目P01至P06作为补查目标，仍不能取得完整内容就保留待复核。P05的面试题转述不能直接当作正确技术答案。没有找到符合条件的X或YouTube个人记录时，直接报告覆盖不足。

最终交付三个部分。

1. 可核查的来源表，CSV或Excel均可，并保留被排除材料及具体理由。
2. 入选内容的独立摘要，保留成功、失败、尚未有结果等不同经历，不编造学生第一人称故事，不整篇搬运原文。
3. 给页面设计的建议，说明哪些信息适合标题、摘要、标签、正文和作者可跳过的写作提示。评论需求写成读者可能提问，不伪造成真实评论。

请区分资料归纳和产品建议。此次研究不修改项目功能范围，也不把个人面经总结成某公司的统一题库、录用保证或薪资标准。无需制作PPT或编写前端代码。
