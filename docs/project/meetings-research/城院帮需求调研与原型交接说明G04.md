3 从调研发现到现有需求

调研用于检查已有需求是否能容纳真实经历，不能从少量案例推导整个行业趋势，也不自动增加作者必填字段或扩展后端接口。经历结果、日期和背景的呈现方式在设计评审细化。

| 材料发现 | 页面与写作表达 | 现有需求及模型 |

| 经历起点差异显著 | 卡片/正文展示已知的当时阶段与基础；缺项显示未提供 | FR-C01、FR-C09；Article与Profile |

| 岗位相近不等于专业相同 | 岗位为主入口，专业与公司为可选条件；专业未知不推断 | FR-R02、FR-R03；Article.majorId、Job、Major |

| 多次面试与后续变化 | 正文可写轮次、失败与调整，后续结果可更新；不强制写满模板 | FR-C01、FR-C07、FR-C09；ArticleVersion |

| 通过、Offer、入职和主观体验不同 | 按原始语义写标题摘要，不为便于统计改成单一成功/失败标签 | FR-R05、FR-C01；新增结构化筛选须经需求变更确认 |

| 长文需要定位与重访 | 使用清楚的正文层次、目录和收藏反馈；保留资料出处 | FR-C02、FR-I04、FR-R05；ArticleVersion、Reaction |

| 优质经验中仍有主观判断 | 来源和日期可追溯；不整理为保证Offer的方法、薪资标准或公司黑名单 | FR-R05、FR-M01、FR-M02；Case、ModerationAction |

| 材料不是校园作者授权投稿 | 调研整理署名与原作者分开，链接原文；不补本校认证、真实联系或虚构互动 | FR-A05、FR-I05、FR-I06；认证与公开资料边界 |

3.1 内容准备的交接规则

演示内容可继续使用明确标注的虚构数据；若改用调研摘要，应显示“资料整理”、原作者和来源链接，并按源数据保留未知项。读者追问是编辑整理的问题，不作为已发生的真实评论。来源记录同时保存发布日期、经历时间和后续更新时间，三者分别解释。

视觉原型用于说明页面组织，W01—W14线框用于检查任务和失败场景。以下记录后续确认要点，实际结果按参与者操作和修改复核逐项保存。

| 任务 | 现有设计 | 需求与确认重点 |
