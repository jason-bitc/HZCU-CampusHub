## 3. 产品与设计判断

城院帮的核心是**找到与你目标岗位相关的亲历经验，并判断是否值得阅读和参考**。首页不应做成岗位招聘列表，也不应把大量装饰和运营入口放在经验内容前面。

用户通常会在课间、宿舍或通勤时用手机浏览。因此采用浅色背景、明确的中文标题、足够的触控空间，以及容易回访的收藏入口。视觉品质主要来自信息组织、留白、字体和一致性，不依靠大面积渐变、磨砂玻璃或反复跳动的动画。

采用“整理过的经验册”语言，但不把手机页面画成真实纸张或书本。章节标签、文章目录和明确的经验摘要承接这个概念。

## 4. 视觉规则

| 项目 | 规格 |
| --- | --- |
| 主色 | 深青绿 `#096B5A`，用于主要按钮、选中状态和品牌区域 |
| 页面底色 | 清浅灰绿 `#F4F7F5` |
| 内容表面 | 白色 `#FFFFFF` |
| 主文字 | 深墨绿 `#172E27` |
| 次文字 | 灰绿 `#52675E` |
| 分隔线 | `#E3EBE6` |
| 辅助色 | 浅青绿 `#E5F2EC`；小面积浅杏色 `#F4EBDD`；辅助色不独立传达状态 |
| 中文字体 | iOS 优先 PingFang SC，Android 使用平台中文无衬线字体；小程序使用系统字体保证加载和中文覆盖 |
| 字号 | 页面标题 24px、文章标题 22px、列表标题 17–18px、正文 16px、辅助信息 12–13px |
| 行高 | 阅读正文约 1.7–1.8；列表标题约 1.45 |
| 页面边距 | 以 390px 宽画板为例，两侧 20px；正式实现按小程序布局与设备适配转换 |
| 间距 | 4、8、12、16、24、32px 的统一尺度 |
| 圆角 | 内容区域 12–16px；短筛选标签可使用胶囊形 |
| 图标 | 同一套线性图标，约 1.5–2px 线宽；不使用 emoji 代替功能图标 |
| 动效 | 切换筛选、收藏反馈采用短过渡；不持续播放装饰动效 |

设计稿中的像素值是视觉规格，不能直接把所有 px 数值乘二后视为真机适配完成。正式开发需要验证中文字体、长文案、小屏幕、微信胶囊和底部安全区。

## 5. 四个核心页面

### 首页 / 发现

顶部为“城院帮”和微信胶囊区域。简短引导语说明可以找到同校同学的实习与求职经验，搜索框提示“搜索岗位、公司或经验”。

一级筛选按目标岗位组织，例如全部、C++ 后端、前端、测试；同专业和公司放入次级筛选。不要把学校所有专业和公司一次铺满首页。

一篇重点经验以明显的标题、简短摘要和作者信息展示，下面接连续经验列表。每条内容说明岗位、专业、经验阶段和作者，优先帮助读者判断是否相关。小封面仅用于区分主题，不让图片挤压正文。

底部导航建议“发现 / 收藏 / 创作 / 我的”。这是本轮的导航建议，不改变已确认的产品范围。

### 经验详情

先展示文章题目、岗位与阶段标签、作者和阅读时间，再展示摘要及正文。目录使用“准备路线 / 投递流程 / 面试复盘 / 避坑建议”等有意义的章节。

底部动作包括点赞、非现金投币、收藏和评论。币应明确属于非现金激励，不设计充值或交易入口。阅读正文保持安静，评论与作者信息可以继续下滑访问。

游客可阅读文章；触发认证用户专属动作时进入校园认证引导。认证能力与界面状态在正式开发时实现，视觉稿仅展示其中一种状态。

### 作者主页

展示昵称、头像、专业、作者自行填写的背景和经验文章。示例作者使用虚构姓名，不能编造真实校友经历。

作者选择公开站外联系方式时才展示对应入口，且仅向认证用户开放。真实校园邮箱不公开。没有联系方式时，不展示失效按钮，也不诱导读者索取私人信息。

### 个人中心

展示本人信息和校园认证状态，提供收藏、分享过的经验、草稿、非现金币、反馈与设置入口。校园邮箱保持私密，个人中心只显示认证结果，不把邮箱作为公开身份。

每日奖励采用轻量入口，不以连续打卡和醒目积分榜压过阅读、分享和收藏任务。

## 6. 必须补齐的状态

- 搜索无结果：保留当前条件，给出清空筛选或更换关键词的操作。
- 网络失败：说明加载失败并提供重试，保留已输入内容。
- 未认证：说明认证后可以使用的具体功能，并允许继续阅读。
- 空收藏、空草稿：解释用途并提供对应入口，不展示假数据。
- 内容处理中或已下架：明确说明状态，提供返回路径。
- 作者未公开联系方式：不暴露邮箱，不显示无效联系方式入口。
- 长标题、长专业名称：允许换行或提供完整值的查看方式。
